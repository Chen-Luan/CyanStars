# 社区谱面哈希系统业务需求

## 业务目标

- 内置谱包由于无法获取文件路径，故直接在编译时提供哈希，不进入哈希缓存文件。展示成绩时单独处理
- 基于 BPM、音符与排列、特效，为谱面生成哈希值
- 确保哈希值不随 json 文本顺序调换、空格与缩进格式而变化
- 基于谱面哈希，为将来展示成绩预留接口；成绩以谱面哈希为键，原有以谱包哈希为键的存档预留结构随之调整
- 在玩家修改哈希缓存文件后做到有限的自愈与防篡改
- 谱面哈希带有 `cys0_` 版本前缀
- 哈希位于玩家设备，不进入谱包或谱面（原有谱包哈希字段删除，不再使用）

## 谱面哈希缓存文件

谱面哈希缓存文件（缓存文件）是一个 .json 文件，采用 utf-8 编码。

对于每个玩家谱面生成一个键值对，内置谱面不进入缓存文件。

其键为谱面文件相对路径（从社区谱目录开始，支持玩家重定向目录）。

其值包含以下内容：

- 谱面哈希缓存
- 谱面文件最后修改时间（UTC 时间，精确到秒）
- 谱面文件大小
- 谱包文件最后修改时间（UTC 时间，精确到秒）
- 谱包文件大小

## 文件读写对比

| 对比项       | 谱包索引文件          | 谱面文件                            | 谱面哈希缓存文件 |
|--------------|-----------------------|-------------------------------------|------------------|
| 文件位置     | 包体内置&应用数据路径 | 包体内置&应用数据路径               | 应用数据路径     |
| 文件数量估计 | 1k~10k                | 2k~50k                              | 1个              |
| 读取性能     | 高                    | 很低                                | 中等             |
| 读取时机     | 每次启动游戏时        | 导入后首次启动游戏时&每次进入音游时 | 每次启动游戏时   |

## 哈希加载与计算时机

基于文件读写性能，做以下设计。

启动游戏时：

1. 启动游戏。
2. 在包内和应用数据内扫描谱包索引文件。
3. 根据谱包索引文件拼接谱面文件地址。
4. 针对玩家谱面，根据谱包和谱面文件地址、修改时间、文件大小，与缓存文件对比。为确保成绩展示正确，此过程为阻塞性，后续视情况优化为后台任务。
    - 缓存文件解析失败时，整体重算缓存。
    - 单个缓存条目字段解析失败时，重算该条目对应的谱面哈希。
    - 谱包索引文件解析失败时，跳过该谱包，删除其目录下的缓存条目并记录日志。
    - 谱面文件解析失败时，跳过该谱面，删除其缓存条目并记录日志。
    - 缓存文件中路径存在，但本地未找到的，从缓存文件中删除键值对。
    - 缓存文件中不存在，但本地找到的，读取并计算其哈希，并携带谱面文件与谱包文件的修改时间和大小写入缓存文件。
    - 缓存文件与本地路径匹配，但修改时间或大小不一致的，读取并重算其哈希，并携带谱面文件与谱包文件的修改时间和大小覆盖写入缓存文件。
    - 文件路径、时间、大小均匹配时，不作处理。
5. 启动选曲 UI 并展示成绩，若玩家篡改数据，不做进一步防篡改处理。

进入音游时：

1. 加载谱面文件。
2. 玩家谱面重算谱面哈希，若与缓存文件中的哈希不一致或缺失，则将谱面哈希、谱面文件与谱包文件的修改时间和大小覆盖写入缓存文件；内置谱面直接采用编译时哈希，不写入缓存文件。
3. 进入音游。
